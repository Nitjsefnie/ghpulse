A proven Claudit-style dashboard for external GitHub issues and pull requests

`ghpulse` serves one configured account. It starts with two panels only, reuses Claudit's established application and chart system, and shares GitHub acquisition with a still-standalone `gh-widgets`.

Claudit foundation, pinned gh-widgets data source

Copy the proven Claudit shell, visual tokens, geometry, auth, scheduling, caching and SSE conventions. Pin `gh-widgets` as a submodule and expose a stable acquisition/snapshot API upstream. The dashboard never embeds widget SVGs; `gh-widgets` remains the standalone SVG product.

01 · Scope

The smallest complete product, without placeholder panels.

  • External authored issues and their current outcomes.
  • External authored pull requests and their current outcomes.
  • Time-range and repository filters.
  • A concise summary strip, health state, scheduled ingest and live refresh.
  • No inspector, qualitative analysis, OAuth, private data, or additional metrics.

03 · Current-state model

There is one row per current GitHub object, not a transition ledger.

TableIdentityCurrent fields
repositoriesGitHub node IDowner/name, owner, URL, visibility, external flag, observed timestamps
issuesGitHub node IDrepository, number, URL, created/updated/closed, state, state reason
pull_requestsGitHub node IDrepository, number, URL, created/updated/closed/merged, state, merged
ingest_runs / sync_staterun ID / singletonprogress, counts, errors, last successful high-water mark

An upsert replaces prior state. Therefore reopening or reclassifying an item removes its former derived outcome without retaining a misleading mid-state.

04 · Event semantics

Each item contributes its creation and at most one current final outcome.

PanelSeriesTimestampPredicate

IssuesCompletedcurrent closed_atCLOSED + COMPLETED
IssuesNot plannedcurrent closed_atCLOSED + NOT_PLANNED
PRsOpenedcreated_atEvery external PR
PRsMergedcurrent merged_atCurrently merged
PRsClosed unmergedcurrent closed_atCurrently closed, not merged

Open is derived, never stored as an event series. A changed final state removes the old event and adds the current outcome at its current outcome timestamp.

05 · Charts and UI

Exact Claudit styling with one bounded extension of its tested time-series component.

  • Stacked interval bars for the three event series.
  • Three matching cumulative lines on the right axis.
  • Cumulative values reset to zero at the selected range's left edge.
  • Adaptive bins, exact partial-final-bin bounds, responsive label measurement and the existing tooltip grammar.
  • Repository and range filters apply to creation and outcome events alike.
  • Summary: repositories, issue outcomes/open, PR outcomes/open, and ingest freshness.

06 · Synchronization

Hourly incrementals make it fresh; complete resyncs make it correct.

Cold and weekly full sync

Cursor-page the complete public authored history without silent limits. Delete unseen rows only after every page succeeds. Refresh identity and organisations, then reclassify all stored repository owners.

Hourly incremental sync

Fetch items updated since an overlap before the last successful high-water mark. Advance the mark only after all pages succeed. Incremental runs never infer deletions. A non-blocking process lock prevents overlap.

After change

Atomically export the versioned snapshot, invalidate the stale-while-refresh response cache and broadcast `ingest_done` over SSE.

07 · Authentication and guest access

Reuse Claudit's separate auth database, PBKDF2 verification, HMAC-signed HttpOnly cookies, origin checks, login throttling and guest sentinel. Both authenticated and guest sessions may view aggregate public data and use repository/range filters. The GitHub token and internal snapshot never reach the browser. Admin ingest requires `X-Admin-Token`.

08 · Failure behavior

  • Incomplete GraphQL pagination fails loudly instead of committing partial truth.
  • Failed incrementals preserve rows, high-water state and the last good response.
  • Failed full syncs never reconcile deletions.
  • Unknown outcome reasons remain stored but unclassified.
  • Missing outcome timestamps are warned and never guessed.
  • Incompatible snapshots are rejected; standalone widget fetching still works.

09 · Verification

  • Fixture-driven pagination, overlap, reconciliation and rollback tests.
  • State-switch tests prove prior outcomes disappear exactly once.
  • API tests for range, repository, guest, current-open and empty data.
  • Geometry tests for stacked sums, three zero-based cumulative lines, partial bins, bounds, labels and tooltips.
  • Existing gh-widgets standalone suite remains green.
  • Full pytest, lint, type, JavaScript syntax, secrecy and control-character gates.
